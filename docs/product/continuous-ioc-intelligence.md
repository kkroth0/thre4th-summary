# Continuous IOC intelligence

The persistent IOC inventory joins news evidence, public OTX pulses, ThreatFox, MalwareBazaar and AbuseIPDB records by a normalized indicator. News supplies source-specific actor/malware/CVE mentions; ThreatFox and MalwareBazaar supply their declared malware labels; OTX supplies pulse context. AbuseIPDB supplies IP reputation, never actor or malware attribution. Reporter handles are not threat actors. These distinctions remain on each evidence record.

Storage: `server/.ioc-intelligence.sqlite`, indexed SQLite in WAL mode, batched writes yielding to requests. The database and sidecars are excluded from Git and all deployment snapshot/sync/rollback operations. Repeated records are upserted by scope, provider, external record and indicator. News fingerprints avoid re-ingesting unchanged publications. Catalogues and actor profiles consume the stored evidence. API observations from personal lookups remain scoped to the authenticated owner; shared queries cannot reveal another account's records or private OTX pulses.

Background schedules: OTX every 15 minutes, with two bounded pages per pass and a persistent cursor/watermark; ThreatFox every hour with a seven-day overlap; MalwareBazaar every 30 minutes with the previous hour's additions; AbuseIPDB blacklist every six hours (four calls per day, 1,000 records, minimum confidence 90). Missing/rejected credentials and quotas are distinct health states. Upstream rate-limit resets postpone retries; failure preserves existing intelligence. Only metadata is collected, never malware files or exploit execution.

Authenticated provider lookups also feed the inventory on a fresh successful API response. Repeated cached lookups create no extra provider call. News import and manual enrichment persist their own evidence without distributing a multi-source IOC union to unrelated actors. An unchanged publication skips event reconstruction only when its content hash, extraction version and every persisted evidence field match; changed score/entity/IOC metadata still triggers correlation.

News and IOCs includes an IOC inventory view: paginated IP/domain/URL/hash search, source health, related entities and a drawer showing original-source evidence. Inventory CSV/JSON exports respect the selected period and the account scope. Actor and malware views retain source references and incorporate API evidence. Unknown malware labels explicitly reported by a provider are represented as source-backed families, without claiming Malpedia coverage.

Primary protocol references: [ThreatFox](https://threatfox.abuse.ch/api/), [MalwareBazaar](https://bazaar.abuse.ch/api/), [AbuseIPDB](https://docs.abuseipdb.com/), [OTX SDK](https://github.com/AlienVault-OTX/OTX-Python-SDK).

Bulk enrichment is a separate workbench. It defaults to every compatible provider, reads all paginated inventory evidence and historical publication mentions, and renders provider columns directly in the results table. CSV includes complete raw provider JSON, formatted data, references, timelines, quotas, publications, correlated evidence and explicit errors; JSON preserves the complete rows. TXT is explicitly an indicators-only export. Missing evidence is distinguished from failed context queries. Provider responses stay subject to upstream access, endpoint coverage and quotas.
